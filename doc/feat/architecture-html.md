# 可索引的 HTML 系统文档（architecture-html）

> 先于实现编写。本文约束四件事：**文档必须覆盖每一个源文件**、
> **任意页面都能一眼定位到任意模块**、**离线可读不依赖任何 CDN**、
> **JS 失效时仍是可用的文档**。

## 问题

### 现状

`doc/feat/*.md` 共 12 篇，每篇记录**一次功能是怎么改的**——它们回答
"为什么这样设计"，不回答"现在系统长什么样"。

要弄清"现在系统怎么跑起来"，只能：

1. 直接读 `src/`，共 53 个源文件、约 9000 行；
2. 或者等一个熟悉的人口头讲一遍。

### 根因

- **没有"当前状态"的文档**。feat 文档是变更记录（时间轴），不是快照（横截面）。
- **没有索引**。Markdown 靠标题层级导航，跨文件检索只能靠 grep。
- **组件数量已经过阈值**。`use-chat-store.ts` 单文件 2129 行、`chat-main.tsx`
  917 行、`chat-sidebar.tsx` 774 行、`favorites-panel.tsx` 797 行——靠记忆维持
  "谁调谁"已不可靠。

### 证据

`README.md` 的「功能」一节列了 40 余条用户可见能力，但**没有任何一句**
说明这些能力由哪些模块实现。新人从 README 无法推导出代码结构。

## 目标

产出一份**系统快照文档**，满足：

| 要求 | 判据 |
|---|---|
| 完整 | `src/` 下每个 `.ts/.tsx` 文件都在文档里有一席之地 |
| 可索引 | 左侧固定目录树，顶部搜索框，任意模块 2 次点击可达 |
| 分层 | 按「入口 → 状态 → 领域 → 视图 → 基座」组织，而非按目录顺序 |
| 简洁 | 每个模块 1 句职责 + 必要时的输入/输出/依赖，不贴代码 |
| 离线 | 零外部请求，双击 `index.html` 即可阅读 |
| 降级 | JS 关闭时目录仍是可用链接，不白屏 |

**非目标**：不替代 `doc/feat/*.md`（那是决策记录），不生成 API 文档
（没有对外 API），不自动从源码抽取（会把注释噪音带进文档）。

## 设计

### 一、信息架构

文档按**运行时层次**切分，而不是按 `src/` 的目录结构——目录结构会随重构
变化，运行时的分层是稳定的：

```
┌─────────────────────────────────────────────────┐
│ L0 入口层    main.tsx / App.tsx / index.html     │  挂载、布局、主题
├─────────────────────────────────────────────────┤
│ L1 状态层    use-chat-store.ts / lib/storage.ts  │  单一真值 + 持久化
├─────────────────────────────────────────────────┤
│ L2 服务层    lib/deepseek.ts                     │  SSE 流式协议
├─────────────────────────────────────────────────┤
│ L3 领域层    features/board-v2/{model,interaction}│  纯函数，无 React/DOM
├─────────────────────────────────────────────────┤
│ L4 视图层    components/* + board-v2/view/*      │  渲染与事件翻译
├─────────────────────────────────────────────────┤
│ L5 基座层    components/ui/* + lib/{hue,utils}   │  无业务语义的原语
└─────────────────────────────────────────────────┘
```

依赖方向**只允许自上而下**。唯一例外是 `L4 ↔ L1`：视图拿到 `store` 对象后
直接调方法，不经过中间层——这是刻意的，用一个 `store` 参数换掉了 90 个
回调的层层透传。

### 二、页面划分

| 文件 | 内容 | 为什么不合并 |
|---|---|---|
| `index.html` | 系统总体运行脉络 + 全模块索引表（53 行表格） | 首屏要能回答"系统怎么跑" |
| `modules.html` | 按 L0–L5 分层的模块详情 | 详情页会很长，与总览分开可独立滚动 |
| `data.html` | 数据模型（`ChatState` 全字段）+ 存储布局 + 术语表 | 跨模块查询频率高，独立成页便于锚点复用 |
| `flows.html` | 四条主链路时序：发消息 / 画板执行 / 保存 / 画板几何变更 | 用图讲比用文字讲快一个数量级 |
| `assets/doc.css` | 全部样式 | 单文件，便于主题统一改 |
| `assets/doc.js` | 搜索过滤、滚动锚点高亮、侧栏折叠 | 无构建步骤，浏览器直接跑 |

### 三、导航机制

**左侧栏**（固定、可折叠）：

- 树形目录，三级：页面 → 大节（h2）→ 小节（h3）；
- 目录由 `doc.js` **在加载时从各页 DOM 抽取**，不手写第二份——
  手写目录与正文必然漂移；
- 当前页高亮，页内滚动时随 `IntersectionObserver` 同步高亮当前小节。

**顶部搜索**：

- 输入即过滤侧栏目录项（按标题文字子串匹配），不索引正文——
  索引正文会让文档体积翻倍，而"按模块名找模块"是真实需求；
- 空结果给出提示而不是空白。

**跨页锚点**：任意页面可用 `modules.html#slug` 直达，索引表里的模块名
全部是链接。

### 四、单文件降级

`doc.js` 只做**增强**，不做**必需**：

- 目录树在 HTML 里就是嵌套的 `<a>`，JS 只是给它们加过滤与高亮；
- 搜索框在 JS 失效时可见但不响应，不报错、不遮挡内容；
- 所有样式在本地 `doc.css`，无 `@import` 外链、无 Google Fonts。

**验收**：`curl` 拿到 HTML 后不做任何 JS 执行，`grep href=` 能得到完整目录。

### 五、覆盖度校验

文档最大的风险是**过时**——新增模块忘了写，读者就找不到。所以要有测试：

`scripts/test-doc-html.cjs` 断言：

1. `src/` 下每个 `.ts/.tsx` 的相对路径都出现在 `doc/html/*.html` 中；
2. 所有 `href="..."` 指向的本地文件存在；
3. 所有 `href="page.html#anchor"` 形式的锚点在目标页存在 `id="anchor"`；
4. 页面不含 `http://` / `https://` 的 `src=` / `href=`（外部 CDN 防回归）；
5. 每页都有 `<nav>` 目录与至少一个 `<h1>`。

第 1 条是核心：**新增源文件而不更新文档 → 测试红**。

## 实现

顺序：

1. `doc/html/assets/doc.css` —— 先定版式，后面只填内容；
2. `doc/html/assets/doc.js` —— 目录抽取、搜索、高亮；
3. `doc/html/index.html` —— 总体脉络 + 索引表；
4. `doc/html/modules.html` —— 分层详情（工作量主要在这里）；
5. `doc/html/data.html` + `flows.html`；
6. `scripts/test-doc-html.cjs`。

## 风险与兜底

| 风险 | 兜底 |
|---|---|
| 文档与代码漂移 | 覆盖度测试（新增文件不写文档即失败） |
| 索引表手写易错 | 模块路径写成 `src/xxx.ts` 形式，可被 `grep -F` 机械校验 |
| 详情页过长难读 | 每层用「折叠分组」，默认展开 L0–L2 |
| 双击打开时 `file://` 下相对路径失效 | 所有链接用相对路径，不用根路径 `/` |

## 验收

- [ ] `src/` 全部 53 个文件在文档中出现
- [ ] `node scripts/test-doc-html.cjs` 通过
- [ ] `file://` 直接打开 `doc/html/index.html`，目录可跳转
- [ ] 页面无任何外部网络请求
