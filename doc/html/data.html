    数据模型与术语

    全部类型定义在 src/lib/types.ts。这里只列字段含义与相互引用关系， 不重复类型语法（看源码更快）。

    实体关系

    Project 1 ──── n Conversation 1 ──── n Message │ │ │ │ │ │ (引用，不复制) │ │ ▼ │ │ BoardNode.ref │ │ │ │ └──── Favorite ──────┘ (conversationId + messageId) │ │ │ └─ n Tag（多对多，存 tagIds） │ └── n Board（也可 projectId = null 表示跨项目共享） │ ├── n BoardNode ──┐ │ │ from / to（有向） ├── n BoardEdge ──┘ │ │ │ └── 被 BoardTask.edgeIds 引用 │ └── n BoardTask
    关键设计：BoardNode 对消息只存 {conversationId, messageId}，不复制正文。 源消息更新卡片跟着变；源消息删除时由 gcBoardRefs() 清理。 用户在卡片上改写时写入 contentOverride，此时卡片与源消息脱钩。

    ChatState 全字段

    字段类型说明
    projectsProject[]项目列表，首次进入自动建一个
    conversationsConversation[]全部对话，含消息正文
    favoritesFavorite[]收藏实体，独立于消息
    tagsTag[]收藏用的标签，带色相
    boardsBoard[]画板
    boardNodesBoardNode[]全部画板的卡片（扁平存放，靠 boardId 区分）
    boardEdgesBoardEdge[]连线
    boardTasksBoardTask[]任务（一组边）
    activeProjectIdstring | null当前项目
    activeConversationIdstring | null当前对话
    activeBoardIdstring | null当前画板
    activeTaskIdstring | null当前任务
    mainView"chat" | "board"主视图（决定画板面板开合）
    apiKeystringDeepSeek Key，明文存 localStorage
    baseUrlstring默认 https://api.deepseek.com
    modelstring默认 deepseek-v4-pro
    thinkingEnabledboolean是否展示思维链
    sidebarView"list" | "tree"侧栏平铺 / 分支树
    安全提醒：apiKey 以明文存在 localStorage。 任何能在该域执行 JS 的东西（含浏览器扩展）都能读到它。 这是纯前端直连模型的固有代价。

    实体逐个说明

    Conversation

    字段说明
    id / projectId所属项目
    title首条用户消息前 24 字，可手动改
    messages消息数组，顺序即时间序
    branchedFrom分支来源：{conversationId, conversationTitle, messageId}。用于侧栏树视图与画板落点
    hue侧栏颜色标记（色相 0–360）
    pinned / archived置顶 / 归档

    Message

    字段说明
    role"user" | "assistant"
    content正文（Markdown）
    reasoning思维链，可折叠展示
    streaming流式进行中。持久化时强制置 false
    error失败信息。带此字段的消息不会被再次发给模型
    favorite / favoritedAt已废弃，启动时迁移到 Favorite 并清除

    BoardNode

    字段说明
    kind"message"（引用型） / "note"（便签）
    ref{conversationId, messageId}，仅 message 型
    excerpt只摘录部分文字时保存的片段，空 = 整段引用
    contentOverride用户改写或执行产出。存在时优先于 excerpt/源消息，UI 标「已改写」
    note用户批注；便签型的正文也在这里
    x / y画布坐标（左上角）
    width / height用户拖拽过的尺寸；空 = 默认宽度自适应内容
    expanded展开显示完整正文
    runsNodeRun[]，最新在前，上限 50
    hue颜色标记

    正文优先级（重要）

    contentOverride （用户改写 / 连线执行结果） ↓ 不存在时 excerpt （划词摘录的片段） ↓ 不存在时 源消息 content （kind = message） note （kind = note，便签只有这一层）

    BoardEdge

    字段说明
    kind"manual" | "reference" | "branch" | "flow"
    label线条文字：画在线上，任何线都能有
    prompt执行提示词：送模型的要求，仅 flow 有意义
    enabledundefined 视为 true；任务运行时过滤
    sourceHandle / targetHandle四向连接点标识，避免节点换边后连线错位
    hue线的颜色
    promptHue旧字段：提示词徽章的独立颜色。新数据不再写，读时回落
    label 和 prompt 为什么要分开：它们是两件事。 "这条线表示 A 依赖 B" 是给人看的文字；"把材料改写成摘要" 是给模型的要求。 早期版本只有一个字段，导致给线写个说明就意外变成可执行提示词。

    NodeRun

    一次连线执行的快照：edgeId、prompt（当时的）、 inputs[]（当时的输入材料）、output、可选 error。 即使之后改了线，历史仍显示当时的值。

    BoardTask

    用户显式挑选的一组边，构成一次可反复执行的上下文组织。 不做拓扑排序、不自动串联——每条边都是独立执行单元。

    Favorite / Tag

    收藏是独立实体，携带自己的 tagIds 与 note。 标签有 name 与 hue。删除消息时收藏被 GC。

    术语表

    术语含义
    hue色相角 0–360。所有"颜色"都以它存储而非 RGB，由 lib/hue 派生明暗两套
    引用型节点kind="message"，指向一条真实消息的画板卡片
    便签节点kind="note"，自由文本，也是连线执行的落点
    可执行边kind="flow" && enabled !== false，由 isRunnableEdge() 判定
    线条文字edge.label，画在线上给人看
    执行提示词edge.prompt，送模型的要求
    即执行边编辑器里的一个开关，同时控制 kind 与 enabled
    已改写节点有 contentOverride，与源消息脱钩
    GCgcBoardRefs()，递归清理悬空引用（画板→节点→边→任务）
    落点新卡片放置的坐标，由 placeCard() 计算，保证不重叠
    BFS/分支树侧栏 tree 视图，按 branchedFrom 构建
    划词浮层选中文字后出现的小窗，独立发起请求，不写入对话
    思维链SSE 的 reasoning_content，存于 message.reasoning
    贴底滚动位置距底部 < 80px，此时自动跟随新内容
    幽灵 input勾选框底层被平移出视口的真实 checkbox，平板系统仍会绘制它
