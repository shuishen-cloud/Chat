    系统总览

    纯前端 DeepSeek 对话客户端，无后端。数据全在 localStorage， 模型调用由浏览器直连 DeepSeek 的 OpenAI 兼容接口。 本文档是系统的横截面快照——描述"现在长什么样"，而非"改了什么"。

    一屏看懂

    浏览器 │ ├─ index.html ──> main.tsx ──> App.tsx ──────────────── L0 入口层：布局 + 主题 │ │ │ ├── useChatStore() ─── L1 状态层：唯一真值 │ │ │ │ │ ├── loadState / saveState ──> localStorage │ │ │ │ │ └── streamChat() ───────────> api.deepseek.com │ │ (SSE) │ │ │ ├── ChatSidebar / ChatMain ── L4 视图层 │ │ │ └── BoardPanel (lazy) │ └── BoardView ──── L3 领域层（纯函数） │ └── React Flow 画布 L4 视图层 │ └─ 渲染：React 19 + Tailwind v4 + shadcn/ui(Base UI) ──── L5 基座层
    一句话：一个 2100 行的 store 装着全部状态， 一个 SSE 模块负责说话，一个纯函数画板模块负责算数，其余都是画布。

    六层结构

    依赖方向只允许自上而下。唯一例外是视图层直接持有一个 store 对象并调它的方法——这是刻意的，用一个参数替代了上百个回调的层层透传。

    层目录职责约束
    L0 src/main.tsx src/App.tsx 挂载、整体布局、主题切换、对话框开合 不持有业务数据
    L1 src/hooks/use-chat-store.ts

    应用启动时序

    1. loadState() 从 localStorage["shadcn-chat/state/v1"] 反序列化； 同时做两件清理：旧版 message.favorite 迁移成独立 Favorite 实体、 gcBoardRefs() 丢弃指向已删消息的画板节点。
    2. 首次进入（无项目）自动建「我的项目」+ 一个空会话。
    3. App 渲染布局：左 ChatSidebar、中 ChatMain、 右 BoardPanel（懒加载，未打开画板时不下载 @xyflow/react）。
    4. 此后任意 setState → 防抖 200ms → saveState() 回写。
    为什么没有后端：API Key 由用户在设置里填、存本地。 这样部署只是一份静态文件（nginx 托管 dist/）， 代价是换设备要重新填 Key，且无法做服务端限流。

    贯穿全局的四个约定

    约定 1 props 传 store，不传回调

    所有视图组件接收一个 store: ChatStore，自己按需取方法。 这样做的好处是新增动作不需要改中间层的签名；代价是组件与 use-chat-store 强耦合，无法单独复用到别处。

    约定 2 引用而非复制

    画板卡片只存 {conversationId, messageId}，不复制消息正文。 源消息变了卡片跟着变，删源消息时由 gcBoardRefs() 清理悬空引用。 用户改写时写入 contentOverride，此时卡片与源消息脱钩（UI 标「已改写」）。

    约定 3 纯函数可测

    几何、落点、长按判定、选区还原、连线配色全部是纯函数，可脱离浏览器测。 画板的 model/ 与 interaction/ 目录下不 import React。

    约定 4 hue 是唯一配色模型

    节点、连线、会话、标签的"颜色"都没存 RGB，而是存色相角 0–360。 hue.ts 从角推导底色/边框/文字，并强制给出明暗两套值—— 暗色复用浅色亮度会过曝。
