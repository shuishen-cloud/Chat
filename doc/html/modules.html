    L1 · 状态层

    src/hooks/use-chat-store.ts 系统中枢 · 2129 行 含副作用

    整个应用的唯一真值。一个 useState<ChatState> 装下所有业务数据， 外加约 80 个动作方法。所有视图组件通过 props.store 拿到它。

    核心导出
    useChatStore() → ChatStore；type ChatStore
    内部机制
    stateRef：与 setState 同步更新的 ref， 让异步循环（如任务执行 for 循环）能立刻读到上一条刚写入的结果，不依赖过期闭包。
    abortRef：持有当前 AbortController，stop() 用它中断流。
    防抖持久化：useEffect 200ms 后 saveState()； 失败仅提示一次。
    方法分组
    项目 add/rename/delete/selectProject
    对话 add/select/rename/delete/clear/move/duplicate/togglePin/toggleArchive/unarchiveAll
    消息 send/stop/regenerate/branchFrom/exportMarkdown/jumpToConversation
    收藏 toggleFavorite/setFavoriteTags/setFavoriteNote/removeFavorites/tagFavorites
    标签 addTag/renameTag/deleteTag/tagCounts
    画板 addBoard/selectBoard/renameBoard/deleteBoard
    节点 addMessageToBoard/addMessageToBoardSmart/addMessagesToBoard/addExcerptToBoard/addConversationToBoard/addNote/moveNode/updateNode/removeNodes/setNodeHue
    连线 connectNodes/removeEdge/updateEdge/setEdgeLabel/setEdgeInstant/toggleEdgeKind/toggleEdgeEnabled/setEdgeHue
    任务 addTask/renameTask/deleteTask/selectTask/toggleTaskEdge/runTask/runEdge/stopTask
    结果 applyRun/restoreNodeContent/nodeText
    依赖
    lib/storage、lib/types、lib/deepseek、 features/board-v2/model/layout（placeCard）
    关键实现
    execEdge() 是单条连线执行的唯一实现， runEdge（单跑）与 runTask（跑一组）都调它， 保证两者语义完全一致。
    已知痛点：2129 行单文件，集合了 8 类实体的增删改。 增加功能时容易继续膨胀；任何 state 变化都会让持有 store 的组件整体重渲染。
    src/lib/storage.ts 持久化与清理 含副作用
    导出
    loadState()、saveState()、 gcBoardRefs()、withBoardGc()、nextTitle()
    存储键
    shadcn-chat/state/v1（单一 JSON）
    loadState 做的三件事
    1. 所有 message.streaming 置 false（刷新后不可能还在流）；
    2. migrateLegacyFavorites()：旧版 message.favorite 转成独立 Favorite 实体，并清掉旧字段（幂等）；
    3. gcBoardRefs() 清悬空引用；activeBoardId/mainView 指向已删除对象时回退。
    gcBoardRefs
    递归清理链：画板 → 节点（引用的消息还在吗）→ 边（两端节点还在吗） → 任务（引用的边还在吗）。所有删除类动作复用这一条链。
    兜底
    loadState 整体 try/catch，解析失败返回空状态； saveState 返回 boolean，配额满时由上层 toast 提示。
    src/lib/types.ts 领域类型总表 纯函数
    内容
    全部 interface 与 type 的唯一出处： ChatState、Conversation、Message、 Favorite、Tag、Board、BoardNode、 BoardEdge、BoardTask、NodeRun。
    同时含工厂函数
    createProject / createConversation / newMessage / createBoard / createBoardNode / createNoteNode / createBoardEdge / createBoardTask， 以及 uid()。类型与工厂放在一起是刻意的——新增字段时 工厂与类型在同一屏，不容易漏。
    常量
    MODELS（3 个模型）、DEFAULT_MODEL、 BOARD_NODE_W/H、TAG_HUES、isRunnableEdge()
    注意
    该文件被 model/doc.ts 反向导入 NodeRun。 这不是循环依赖（doc.ts 只取类型），但需留意。

    L2 · 服务层

    src/lib/deepseek.ts SSE 流式客户端 含副作用
    导出
    streamChat(opts) → Promise<{content, reasoning}>、 DeepSeekError
    输入
    { apiKey, baseUrl, model, messages, thinkingEnabled, signal, onDelta, onReasoning }
    协议
    POST {base}/v1/chat/completions，stream: true； 用 ReadableStream.getReader() 读，按 \n\n 切 SSE 事件， 逐行取 data:，[DONE] 跳过。
    增量通道
    onDelta 正文、onReasoning 思维链 （reasoning_content）。
    请求体净化
    发出前过滤掉 error 消息与空内容消息—— 否则重试一条失败消息会把错误文本再喂给模型。
    思考开关的保守实现
    thinkingEnabled=false 时不发送任何非标参数， 只是丢弃 reasoning_content。因为 DeepSeek 未公开思考开关字段， 发送未知字段可能导致整个请求被拒。
    兜底
    非 2xx 时解析 error.message 拼成可读错误； 无 response.body（旧浏览器）直接抛错。

    src/features/board-v2/model/layout.ts 落点计算 · 468 行 纯函数
    导出
    placeCard(input) → {x, y}、 findBranchParent()、findPreviousCard()、LAYOUT_GAP
    要解决的问题
    新卡片不许与任何已有卡片重叠。旧实现用 "已有卡片数取模"算网格，删卡后计数回流就把新卡压到旧卡上。
    策略（优先级）
    1. 贴分支父卡片（向右偏移）；2. 接同对话上一条卡片（向下）； 3. 全画布扫描空位；4. 扫描上限用尽则在大包围盒右侧新开一列。
    不变量
    任何输入都返回有限坐标（NaN/非法尺寸被夹紧）； 绝不移动已有卡片——用户拖过的位置是高价值信息。
    调用方
    use-chat-store 的 planPlacement()， 被 5 个"加入画板"入口复用。
    src/features/board-v2/model/map.ts 模型互映射 · 222 行 纯函数
    导出
    toFlow(doc)、fromFlow(...)、CardData
    约定
    业务字段全部塞进 data.card； 框架字段（position/width/height/selected）归 React Flow。 映射必须可逆：fromFlow(toFlow(doc)) 与 doc 字段级等价。
    依赖
    @xyflow/react（仅类型）、dot.ts、view/edge-meta.ts
    src/features/board-v2/model/resize.ts 缩放几何 · 71 行 纯函数
    导出
    resizeNode(box, dir, delta) → Box、dirAffects()、ResizeDir
    为什么独立成文件
    v1 的 bug「往左拉却向右长」根因是缩放几何由 React Flow 内部算、又被业务 store 用旧尺寸覆盖。现在唯一决定盒子怎么变的地方就是这里， 方向不变量可以逐条断言。
    约束
    八向（n/s/e/w + 四角）；最小尺寸夹紧；向西/北拉时同步修正 x/y。
    src/features/board-v2/interaction/machine.ts 交互状态机 · 120 行 纯函数
    导出
    Interaction（联合类型）、transition()、InteractionKind
    状态
    idle | dragging | resizing | connecting | marquee | edge-menu
    要解决的问题
    v1 的"抢交互"：拉线抢拖拽、缩放手柄抢节点拖动。 这里改为只在该状态下才挂对应事件，不靠 CSS 层级和 opacity 去错开。
    src/features/board-v2/store-adapter.ts 形状转换层 纯函数
    导出
    toDoc(boardNodes, boardEdges, boardId) → BoardDoc
    职责
    把 store 的 BoardNode/BoardEdge 投影成领域 BoardDoc。view/ 不该知道 store 的形状，model/ 更不该—— 所有形状转换集中在这一个文件。
    调用方
    features/board-v2/index.tsx，用 useMemo 按 [boardNodes, boardEdges, boardId] 缓存。
    src/features/board-v2/index.tsx 子系统唯一出口
    导出
    BoardView（组件）、type BoardDoc
    职责
    接 store → 投影 BoardDoc；把画布回调翻译成 store 方法调用。 不持有画板业务状态——doc 完全由 store 派生，用 useMemo 重算。
    设计意义
    内部结构（model / interaction / view）不对外泄漏， 以后调整内部实现不会波及 BoardPanel。
    props
    store、boardId、dark、 edgePickMode、selectedEdgeIds、executingEdgeId、 editingEdgeId，以及 6 个回调。

    src/features/board-v2/view/board-canvas.tsx React Flow 挂载 · 619 行
    职责
    挂载 React Flow；把画布事件翻译成领域文档变更，提交回 store。 不写业务规则。
    关键约束
    唯一真值 = React Flow 的 useNodesState/useEdgesState；
    不过滤 NodeChange（position/dimensions/select 全交给 applyNodeChanges）；
    不用 useEffect 把数据反向写回 store。
    提交时机
    拖拽在 onNodeDragStop、缩放在松手时由 commitGeometry 一次性落库——几何变更期间不写 store， 避免两份坐标互相覆盖。

    @xyflow/react、cards/*、handles、 resize-controls、edge-meta、long-press、 use-refresh-node-internals、interaction/machine

    src/features/board-v2/view/long-press.ts 长按判定 · 118 行 纯函数
    导出
    useLongPress()、纯函数部分、LONG_PRESS_MS=500、LONG_PRESS_MOVE_TOLERANCE=6

    长按的 90% 是"什么时候不该触发"——中途位移、提前抬手、 组件卸载。写成纯函数后可用假时钟覆盖，不必开浏览器。

    src/features/board-v2/view/resize-controls.tsx 缩放手柄 · 161 行
    职责
    八向手柄 + 四条边线。只做一件事：把拖拽手势翻译成 resizeNode() 的调用。
    写入策略
    拖动过程中把结果直接写回 React Flow store（setNodes）， 松手时由画布的 commitGeometry 一次性落库—— 尺寸与坐标永远同源、同帧、同一次写库。这是 v1「往左拉向右长」的修复方式。
    依赖

    src/features/board-v2/view/use-refresh-node-internals.ts 量测刷新 · 34 行
    职责
    卡片内容/尺寸变化后调用 React Flow 的 updateNodeInternals，刷新 handle 量测。
    解决的现象
    React Flow 只在首次量测时记录每个 handle 坐标。卡片展开、 打开历史、改写、resize 导致高度变化后，handleBounds 仍是旧值， 连线就画到错误位置——典型表现是"线从卡片上方的空白处出发"。
    为什么单独成文件
    塞进 board-canvas 会拖累 Fast Refresh 边界， 也让画布更难读。

    src/lib/hue.ts 配色派生 · 62 行 纯函数
    导出
    HUE_PRESETS、hueBg、hueBorder、 hueText、hueStroke、hueDot
    模型
    颜色不存 RGB，存色相角 0–360。所有函数签名都带 dark: boolean，强制给出明暗两套值。
    为什么
    暗色主题不能复用浅色的高亮度值，否则刺眼过曝。 把 dark 做成必填参数，编译器就会逼你两边都想清楚。
    使用方
    画板卡片、连线、侧栏会话标记、收藏标签
    src/lib/selection-to-markdown.ts 选区还原 Markdown · 425 行 纯函数
    导出
    rangeToMarkdown(range) → string
    为什么不用 selection.toString()
    表格里浏览器用 \t 连接单元格，丢失表头/分隔行；
